我重新把比赛文件、两份你们自己的机器人材料和《发动机工程设计报告》又对了一遍。**有几个点我上一轮确实漏了，而且有几个还挺关键。**

最重要的是：这份材料不能只是“把已有功能写进去”，还必须**按照评分标准反推写法**。比赛虽然在“材料文档要求”里只列了调研、技术路线、三个模型、工程可行性和技术性能分析，但评分时又单独给了“研究思路合理性”10分，所以正式方案里必须专门把“研究思路”写清楚，不能藏在技术路线里一笔带过。技术路线20分、模型合理性20分，两项加起来占主观分的三分之二。fileciteturn217file15L503-L526

重新审查后，我认为之前还漏了这些关键点：

1. **“研究思路”必须单独突出。**  
   官方要求的不只是已有系统改造，还明确强调“新思路、新框架、新方案”“具有创新特色的系统化定位方法与整体解决方案”。fileciteturn217file9L345-L359  
   所以我们不能写成“GNSS模块 + LiDAR模块 + 重定位模块”三个独立功能堆起来，而要有一条统一逻辑，例如：  
   **状态感知 → 质量评价 → 自适应融合 → 退化检测 → 主动恢复 → 恢复验证**。  
   三个模型应该是这一套总体方法的三个组成部分。

2. **“平面和高程”这个点之前重视得不够。**  
   官方第一项指标不是简单的“定位误差20 cm”，而是**平面和高程定位精度都优于20 cm**。fileciteturn215file0L157-L165  
   这对我们很重要，因为现有机器人核心导航链本质上还是二维导航。方案书里必须把 XY 和 Z 分开分析，不能最后只拿二维轨迹误差去冒充整个指标。

3. **LiDAR指标不能只写“动态点剔除有效”。**  
   官方真正评分的是：**动态目标剔除以后，相邻帧有效特征重复率 ≥95%**。fileciteturn215file0L157-L165  
   所以模型章节需要回答完整链条：  
   动态/异常点怎么发现 → 怎么剔除 → 什么叫“有效特征” → 相邻帧怎么配对 → 重复率怎么算。  
   后面的技术性能章节也要和这个公式完全对应。

4. **主动重定位不能写成普通“重新定位”。**  
   比赛强调的是“具身主动重定位”，而且背景专门强调传感器质量随机器人运动和环境交互动态变化。fileciteturn215file0L55-L65  
   所以第三个模型必须把：
   **感知退化 → 判断定位不可信 → 主动运动/旋转寻找更有信息量的观测 → 候选位姿 → 多帧验证 → 恢复导航**
   这一整条闭环讲出来。  
   这样才能真正体现“具身”，而不是把 AMCL 重置一下就说是具身智能。

5. **三个模型每一个都要写“为什么这样设计”。**  
   《发动机工程设计报告》这里很值得学。它不是只介绍零件，而是先做需求分析，再列核心部件、功能、实现方案，然后做计算、建模、验证和小结。fileciteturn216file1L170-L215  
   我们也应该对应成：  
   **问题 → 输入 → 核心变量 → 模型/公式 → 状态判断 → 输出 → ROS2实现 → 为什么选这个方案 → 当前验证 → 后续实验。**  
   这样才能真正拿“模型合理性”那20分。

6. **图不能少。之前我更关注文字，这个也漏了。**  
   你们原来的机器人报告其实有现成的“系统架构图、通讯流程图、任务协同架构图”这种写法，而且图和正文是一一对应的。fileciteturn218file0L43-L60 fileciteturn218file0L63-L101  
   新方案至少应该准备：
   - 现有机器人硬件/软件架构图
   - 比赛增强后的总体技术路线图
   - 多源融合模型流程图
   - LiDAR动态特征处理流程图
   - 主动重定位状态机/闭环图
   - ROS2节点与数据流图
   - 后期性能结果图  
   
   这比堆十几页纯文字强很多。

7. **现有机器人基础应该独立写清楚，但不能喧宾夺主。**  
   你们现有系统确实有很好的工程底子：ROS2/Nav2、AMCL、Jetson、LiDAR、IMU、RTK/GNSS、ZED、任务执行和边缘端等都能作为“为什么这个方案能落地”的依据。fileciteturn217file6L249-L265  
   同时，原报告里的 Web、工单、用户权限、市场风险等内容不能大篇幅搬过来。这次重点不是电力巡检业务系统，而是**导航定位技术**。

8. **工程可行性不能只写“我们有机器人，所以可行”。**  
   应该拆成：
   硬件基础、软件基础、算力基础、ROS2集成基础、接口可扩展性、安全降级机制、现场部署能力、潜在技术风险。  
   你们原项目已经有弱网下本地执行、本机急停、Mobile Bridge、ROS2边缘执行等内容，这些都可以用来证明工程成熟度。fileciteturn218file0L43-L50

9. **北斗短报文现在不能完全从材料里消失。**  
   虽然我们当前阶段不做它，但它是官方第四项研究目标，也是10分客观指标。fileciteturn215file0L80-L96 fileciteturn215file0L157-L165  
   所以当前方案至少应该写清楚：  
   “当前尚未完成 → 预留在哪一层接入 → 与ROS2/状态上报怎么衔接 → 后续需要什么硬件/协议确认”。  
   不能假装已经完成，也不能整篇不出现。

10. **技术性能章节不能等有数据以后才开始写。**  
    现在就应该把四项指标分别做成“评价方法 + 指标定义 + 当前已有验证 + 缺失证据 + 后续实测位置”。  
    以后拿到 rosbag、真车数据，只需要把表格和图补进去，不需要重写整章。

11. **正式方案不能保留大量 CURRENT / PARTIAL / TARGET 标签。**  
    这些标签非常适合我们内部控制真实性，但正式比赛报告一直这么写会像项目管理备忘录。  
    正式正文应该改成人话，例如：  
    “目前已完成……”“现阶段通过软件测试验证……”“实车指标将在后续实验中进一步验证……”。  
    内部依然保留状态表，正文不直接暴露管理标签。

12. **参考文献必须重新做，不能照参考报告的引用方式。**  
    《发动机工程设计报告》整体结构值得学，但它的参考文献里直接存在“Simulated textbook”“Representative Chinese paper”这样的占位信息，绝不能复制这种做法。fileciteturn217file8L318-L322  
    我们最后的国内外研究现状必须是真论文、真项目、真官方资料，并且正文引用和文末编号对应。

所以我现在把计划也修正一下。

**下一步我建议还不写正文。**

先做两张内部底表 + 一个最终目录：

**第一张：比赛要求—评分项—方案章节—证据来源矩阵。**  
确保官方每一分都有地方对应，防止“文章写了很多，结果评分点没覆盖”。

**第二张：现有能力证据表。**  
逐项分成“原项目已有 / 比赛新增 / 尚未完成”，并对应到具体代码、配置、文档和已有测试。

然后基于这两张表，给你一版**最终材料文档目录 + 每章写什么 + 预计放什么图表 + 哪些现在能写、哪些留数据位**。

你看完并同意这个骨架之后，我才开始真正重写方案正文。

我认为这样比我之前“直接拿V0.1往下改”稳很多，也更不容易漏比赛评分点。memcite
